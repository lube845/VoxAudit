# VoxAudit 智能质检系统方案设计

## 1. 系统概述

### 1.1 项目背景

随着金融催收行业规模扩大，传统人工质检模式面临效率低、成本高、覆盖率低等痛点。本系统旨在构建一套智能化的录音质检解决方案，实现催收通话的自动转写、AI智能评分与多维度统计分析。

### 1.2 项目目标

- 实现催收通话录音的自动化转写处理
- 基于AI大模型实现智能评分，替代人工抽检
- 提供可视化统计报表，支持多维度数据分析
- 支持规则灵活配置，满足业务个性化需求

## 3. 数据模型设计

### 3.1 核心实体

#### 3.1.1 评分规则 (ScoringRule)

```sql
CREATE TABLE scoring_rules (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    name            VARCHAR(100) NOT NULL COMMENT '规则名称',
    code            VARCHAR(50) NOT NULL COMMENT '规则代码',
    version         VARCHAR(20) NOT NULL COMMENT '规则版本号',
    description     TEXT COMMENT '规则描述(LLM评分依据)',
    total_score     FLOAT DEFAULT 100.0 COMMENT '总分',
    rule_type       ENUM('bonus', 'deduction') DEFAULT 'bonus' COMMENT '规则类型',
    is_veto         BOOLEAN DEFAULT FALSE COMMENT '是否为一票否决规则',
    is_latest       BOOLEAN DEFAULT TRUE COMMENT '是否为最新版本',
    parent_id       INT COMMENT '上一版本ID',
    user_id         VARCHAR(50) COMMENT '所属用户',
    remark          TEXT COMMENT '备注',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME ON UPDATE CURRENT_TIMESTAMP,
    published_at    DATETIME COMMENT '发布时间'
);
```

**设计说明**：
- `code` 用于规则唯一标识，支持版本追溯
- `parent_id` 建立版本链路，支持规则历史版本查看
- `description` 作为LLM评分prompt的核心依据
- `rule_type` 区分加分/扣分两种评分模式
- `is_veto` 标记一票否决规则，触发后录音直接判定不合格

#### 3.1.2 录音文件 (Recording)

```sql
CREATE TABLE recordings (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    file_name       VARCHAR(255) NOT NULL COMMENT '文件名',
    file_size       INT NOT NULL COMMENT '文件大小(字节)',
    file_md5        VARCHAR(32) COMMENT '文件MD5(去重)',
    file_type       VARCHAR(20) NOT NULL COMMENT '文件类型',
    oss_object_key  VARCHAR(500) NOT NULL COMMENT 'OSS对象键',
    oss_bucket      VARCHAR(100) NOT NULL COMMENT 'OSS Bucket',

    agent_id        VARCHAR(50) COMMENT '坐席工号',
    agent_name      VARCHAR(100) COMMENT '坐席姓名',
    customer_phone  VARCHAR(20) COMMENT '客户电话',
    call_id         VARCHAR(100) COMMENT '通话ID',
    call_time       DATETIME COMMENT '通话时间',

    status          ENUM('uploading','uploaded','transcribing','transcribed',
                         'scoring','scored','upload_failed',
                         'transcribe_failed','score_failed') DEFAULT 'uploading',
    duration        FLOAT COMMENT '录音时长(秒)',

    user_id         VARCHAR(50) COMMENT '所属用户',

    transcript      TEXT COMMENT '转写全文',
    transcript_segments JSON COMMENT '转写片段(带时间戳)',

    total_score     FLOAT COMMENT '总分',
    bonus_score     FLOAT DEFAULT 0 COMMENT '加分总分',
    deduction_score FLOAT DEFAULT 0 COMMENT '扣分总分',
    rule_version    VARCHAR(20) COMMENT '规则版本',
    remark          TEXT COMMENT '备注/错误信息',

    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME ON UPDATE CURRENT_TIMESTAMP
);
```

**设计说明**：
- `file_md5` 用于录音去重，避免重复上传
- `status` 状态机确保业务流程可追溯
- `transcript_segments` 存储带时间戳的分句及说话人角色，便于LLM理解对话时序
- 多租户设计 (`user_id`)，支持多用户数据隔离

#### 3.1.3 转写片段 (TranscriptSegment)

```sql
CREATE TABLE transcript_segments (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    recording_id    INT NOT NULL,
    speaker         VARCHAR(20) COMMENT '说话人(agent/customer)',
    speaker_name    VARCHAR(100) COMMENT '说话人名称',
    start_time      FLOAT COMMENT '开始时间(秒)',
    end_time        FLOAT COMMENT '结束时间(秒)',
    text            TEXT COMMENT '文本内容',
    confidence      FLOAT COMMENT '置信度',
    FOREIGN KEY (recording_id) REFERENCES recordings(id)
);
```

#### 3.1.4 评分结果 (ScoringResult)

```sql
CREATE TABLE scoring_results (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    recording_id    INT NOT NULL,
    rule_ids        JSON COMMENT '使用的评分规则ID列表',

    total_score     FLOAT DEFAULT 0 COMMENT '该规则得分',
    bonus_score     FLOAT DEFAULT 0 COMMENT '加分',
    deduction_score FLOAT DEFAULT 0 COMMENT '扣分',
    scoring_details JSON COMMENT '评分详情JSON',
    matched_text    TEXT COMMENT '匹配的原文',

    is_auto_scored  BOOLEAN DEFAULT TRUE COMMENT '是否自动评分',
    is_rejected     BOOLEAN DEFAULT FALSE COMMENT '是否驳回',
    ai_model        VARCHAR(100) COMMENT '使用的AI模型',
    scored_by       INT COMMENT '评分人',
    scored_at       DATETIME COMMENT '评分时间',
    remark          TEXT COMMENT '备注',

    user_id         VARCHAR(50) COMMENT '所属用户',

    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (recording_id) REFERENCES recordings(id)
);
```

**设计说明**：
- `rule_ids` 支持一次评分应用多条规则，兼容复合评分场景
- `scoring_details` 存储LLM返回的详细评分依据，便于结果复核
- `is_rejected` 支持人工驳回AI评分结果
- `ai_model` 记录评分模型，便于结果溯源和模型对比

## 4. 核心流程设计

### 4.1 录音上传与处理流程

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  上传   │───▶│  存储   │───▶│  转写   │───▶│  评分   │───▶│  完成   │
│  录音   │    │  MinIO  │    │  ASR    │    │  AI评分 │    │  存档   │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
     │              │              │              │
     ▼              ▼              ▼              ▼
┌─────────────────────────────────────────────────────────────────┐
│                         状态追踪                                │
│  uploading → uploaded → transcribing → transcribed →           │
│  scoring → scored / score_failed                                │
└─────────────────────────────────────────────────────────────────┘
```

**详细步骤**：

1. **上传阶段**
   - 客户端计算文件MD5，检测是否已上传（去重）
   - 分片上传至后端，后端存储至MinIO
   - 更新录音状态为 `uploaded`

2. **转写阶段**
   - 后端调用ASR服务进行语音转写
   - ASR返回带时间戳的分句结果，自动识别说话人角色
   - 更新录音状态为 `transcribed`

3. **评分阶段**
   - 后端调用AI评分服务
   - AI根据规则description分析转写文本
   - 评分结果写入 `scoring_results` 表
   - 更新录音状态为 `scored`

### 4.2 AI评分流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 获取规则 │───▶│ 构建Prompt│───▶│ 调用LLM  │───▶│ 解析结果 │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                              │
                                              ▼
                                        ┌──────────┐
                                        │ 存储结果 │
                                        └──────────┘
```

**Prompt构建策略**：

```
## 加分规则评分
规则类型：bonus
评分逻辑：匹配description描述 → 获得满分，否则0分

## 扣分规则评分
规则类型：deduction
评分逻辑：违反description描述 → 扣除对应分数，不违反 → 0分

## 一票否决
规则类型：is_veto=true
评分逻辑：匹配到违规描述 → 录音直接判定不合格（总分=0）
```

### 4.3 规则版本管理

```
创建规则v1 ──▶ 创建新版本v2 ──▶ 旧录音用v1，新录音用v2
     │               │
     ▼               ▼
 is_latest=false  is_latest=true
```

**版本控制策略**：
- 规则修改时自动创建新版本，旧版本标记 `is_latest=false`
- 已评分录音保留原规则版本引用 (`rule_version`)
- 新录音自动使用最新版本规则评分
- 支持历史版本查看和回滚

### 4.4 OA认证流程

```
用户登录 ──▶ 用户名/密码 ──▶ OA加密 ──▶ SSO验证 ──▶ 会话创建
                │                                    │
                └──────────────────────────────────────┘
                                Base64(X-User-Info)
```

**认证说明**：
- 支持用户名密码登录和OA单点登录两种模式
- 会话信息通过Base64编码的JSON存储在`X-User-Info`请求头中
- 会话有效期由系统配置，默认24小时

```yaml
      MYSQL_USER: ${DB_USER}
      MYSQL_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: ${DB_NAME}
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]

  cos:

    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: ${COS_SECRET_ID}
      MINIO_ROOT_PASSWORD: ${COS_SECRET_KEY}

  backend:
    build:
      context: ..
      dockerfile: docker/Dockerfile.backend
    depends_on:
      tdsql:
        condition: service_healthy

  frontend:
    build:
      context: ..
      dockerfile: docker/Dockerfile.frontend
```

## 8. 安全设计

- 文件上传校验（MD5去重）

- CORS跨域限制
