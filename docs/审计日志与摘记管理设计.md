# VoxAudit 审计日志查询页面 — 设计方案

> v2 · 2026-09-14 · 待评审

## 1. 目标

记录每个用户（admin / k 客服 / OA）在系统内的**全部页面访问 + 全部操作点击**，后台 admin 可查询。催记管理目前是前端 mock，本次顺便补后端 + 接通。

## 2. 设计要点

| 项 | 结论 |
|---|------|
| 审计范围 | 所有页面 + 所有按钮点击 + 所有二次确认 |
| 查询权限 | 仅 admin |
| 原文 | 审计 `detail` 不存原文 |
| 敏感字段 | 手机号在审计里只存**尾号 4 位** |
| 保留期 | **永久** |
| 去重 | **5 分钟**内同 actor + target + action 只记一次；`result=fail` 不去重 |
| 页面访问降噪 | 默认隐藏 `page.view`（开关 `include_page_view=true` 开启） |

## 3. 埋点策略（三层互补）

| 方式 | 覆盖 | 拿业务上下文 |
|------|------|------|
| 后端中间件 | 所有非 GET API | ❌（自动从 URL 推断 action / target） |
| 后端手动 | 登录、改密、催记 6 动作 | ✅ |
| 前端路由守卫 + utils | 路由切换 + 纯 UI 操作（Tab/筛选） | ✅ |

## 4. 数据模型 `audit_logs`

```python
class AuditLog(Base):
    __tablename__ = "audit_logs"
    id            = Column(BigInteger, primary_key=True)
    created_at    = Column(DateTime, index=True)

    actor_loginid = Column(String(50), index=True, nullable=False)
    actor_name    = Column(String(100))
    actor_role    = Column(String(20))                   # admin / k_user / oa_user

    action        = Column(String(50), index=True, nullable=False)
    target_type   = Column(String(50), index=True)
    target_id     = Column(String(100))
    target_label  = Column(String(255))

    ip            = Column(String(64))
    user_agent    = Column(String(255))
    result        = Column(String(20), default="success")
    detail        = Column(JSON)
```

## 5. 页面 × 操作 × 记录内容

### 5.1 全局

| 触发 | action | 记录什么 |
|------|--------|---------|
| 路由切换（任意页面进入） | `page.view` | `target_type`=页面名，`target_id`=路由路径 |

| 页面 | 点击 | action | 记录什么 |
|------|------|--------|---------|

| /login | 登录失败 | `auth.login_fail` | 尝试的 loginid、IP、UA、`detail.reason` |
| /change-password | 提交改密 | `auth.change_password` | actor |

### 5.3 数据概览 `/home`

### 5.4 规则管理 `/rules`

| 点击 | action | 记录什么 |

| 新增规则 | `rule.create` | `detail.rule_code` / 类型 |

| 删除规则 | `rule.delete` | `target_id`=rule_id，`detail.rule_code` |
| 启用 / 禁用 | `rule.toggle` | `target_id`=rule_id |
| 回滚版本 | `rule.rollback` | `target_id`=rule_id，`detail.from_version` / `to_version` |
| 导入规则 | `rule.import` | `detail.imported_count` / `failed_count` |
| 导出规则 | `rule.export` | `detail.count` |

### 5.5 录音管理 `/recordings`

### 5.7 催记管理 `/collection-notes` ⭐

## 6. 后端 / 前端实现要点

### 6.1 后端中间件自动推断（覆盖所有非 GET）

| URL 模式 | 推断 |
|----------|------|
| `POST /api/v1/rules` | `rule.create` |
| `PUT /api/v1/rules/{id}` | `rule.update`，target_id=`{id}` |
| `DELETE /api/v1/rules/{id}` | `rule.delete`，target_id=`{id}` |
| `POST /api/v1/recordings/{id}/transcribe` | `recording.transcribe`，target_id=`{id}` |

（用 URL 前缀白名单 + 正则覆盖所有写路由。）

### 6.2 后端手动补关键埋点

| 位置 | 额外记录 |
|------|---------|
| `auth.login` 成功 / 失败 | actor、IP、UA、失败原因 |
| `auth.change_password` | actor |
| 催记 6 动作 | `detail.chars` / `lines`（**不存原文**） |

### 6.3 催记后端接口（最小骨架）

| 方法 | 路径 | action |
|------|------|--------|
| GET | `/collection-notes/calls` | — |
| GET | `/collection-notes/calls/{call_id}` | — |
| POST | `/collection-notes/calls/{call_id}/view-structured` | `view_structured` |
| POST | `/collection-notes/calls/{call_id}/view-unstructured` | `view_unstructured` |
| POST | `/collection-notes/calls/{call_id}/edit-structured` | `edit_structured` |
| POST | `/collection-notes/calls/{call_id}/edit-unstructured` | `edit_unstructured` |
| POST | `/collection-notes/calls/{call_id}/save-structured` | `save_structured` |
| POST | `/collection-notes/calls/{call_id}/save-unstructured` | `save_unstructured` |

> 上游通话数据未接，列表接口先返回空。

### 6.4 审计查询接口

| 方法 | 路径 | 权限 |
|------|------|------|
| GET | `/admin/audit-logs` | admin |
| GET | `/admin/audit-logs/actions` | admin |
| GET | `/admin/audit-logs/actors` | admin |
| POST | `/admin/audit-logs/export` | admin |
| POST | `/admin/audit-logs/record` | 任意已登录（前端埋点用） |

`GET /admin/audit-logs` 参数：`actor_loginid` / `action` / `target_type` / `keyword` / `start_time` / `end_time` / `page` / `page_size` / `include_page_view`（默认 false）

### 6.5 前端埋点工具

```js
audit(action, target_type, target_id, detail)
// 内部 5 分钟去重，异步上报，不阻塞 UI
```

接入点：路由守卫（page.view）、筛选按钮、Tab 切换。表单提交 + API 调用由后端中间件覆盖，前端不重复埋。

## 7. 实施步骤

1. 建 `audit_logs` 表 + 迁移
2. 写 `audit_service`（record_action + 5 分钟去重）
3. 写后端中间件 + 注册到 `main.py`
4. 手动补：auth（登录/改密）、催记 6 动作

6. 写审计查询 5 个接口
7. 前端 `utils/audit.js` + 路由守卫 + 各页面关键按钮埋点

## 8. 已确认决策

| # | 决策 | 结论 |
|---|------|------|
| D1 | 摘记后端同步做 | ✅ |
| D2 | 审计范围 | 全页面 + 全操作；仅 admin 查 |
| D3 | 通话数据来源 | 上游未接，本次不接 |
| D4 | detail 存原文 | **不存** |
| D5 | 催记操作 | 6 个：view/edit/save ×2 |
| D6 | 手机号脱敏 | 审计只存尾号 4 位 |
| D7 | 保留期 | 永久 |
| D8 | 埋点方式 | 中间件 + 后端手动 + 前端 |
| D9 | 去重 | 5 分钟；fail 不去重 |
| D10 | page.view 显示 | 默认隐藏（开关控制） |
